# ADR-003: World generation determinism

**Status:** Accepted
**Date:** 2026-08-03
**Applies to:** `src/world/TerrainGenerator.ts`, `src/utils/Noise.ts`, `src/utils/Random.ts`, `src/Constants.ts`

## Context

The world is streamed in chunks around the player and chunks are **unloaded and
re-generated** as the player moves (`ChunkManager.unloadFar` drops chunks
beyond `VIEW_RADIUS + 2`, and they are re-generated from scratch after
`refreshQueue` re-enqueues them). Terrain must therefore be a pure function of
its inputs: re-creating `TerrainGenerator(seed)` and calling
`generate(chunk)` on the same `(cx, cz)` must reproduce the identical block
layout — otherwise the world "mutates" as the player walks away and comes
back, trees would move, cave mouths would shift, and player edits made against
one terrain state would be applied to a different one.

The generator also needs to be **chunk-independent at the borders**: trees can
root up to 2 cells outside a chunk while their canopies overhang in, so any
chunk must be able to regenerate the foliage that belongs to its area.

Finally, generation runs inside a 6 ms/frame budget (`ChunkManager.update`),
so every noise/hash evaluation must be cheap and allocation-free enough to
leave headroom.

## Decision

All terrain is generated by **deterministic seeded functions of world
coordinates — never `Math.random`**:

- **Seeded RNG:** `src/utils/Random.ts` exports `mulberry32(seed)`, a
  deterministic 32-bit PRNG whose state lives in a closure, and `hash2(x, z,
  seed)`, an integer hash of `(x, z, seed)` producing a value in `[0, 1)`.
  JS number arithmetic (`imul`, `>>>`) is used throughout so results are
  identical across platforms (no float-drift dependence).
- **Seeded simplex noise:** `src/utils/Noise.ts` is a port of Stefan
  Gustavson's public-domain simplex implementation. The gradient permutation
  table is initialized by shuffling `0..255` with `mulberry32` draws, so a
  given seed always yields the same permutation. It exposes `noise2`,
  `noise3`, `fbm2`, and `fbm3` (fractal Brownian motion, ≈[−1, 1]).
- **Seed fan-out:** `TerrainGenerator` takes one `seed` and derives four noise
  fields via XOR mixing: `nCont = SimplexNoise(seed ^ 0x1001)`,
  `nHill = SimplexNoise(seed ^ 0x2002)`, `nDetail = SimplexNoise(seed ^
  0x3003)`, `nCave = SimplexNoise(seed ^ 0x4004)`. The seed itself defaults to
  `1337` in `src/core/Game.ts` and is overridable with `?seed=N` in the URL.
- **Heightmap:** `heightAt(x, z)` is fbm over continent/hill/detail octaves —
  `20 + nCont(4 oct) * 9 + nHill(3 oct) * 6 + max(nHill(2 oct) − 0.15, 0) *
  30 + nDetail(2 oct) * 1.5`, clamped to `[1, CHUNK_HEIGHT − 4]` and floored.
  Purely a function of `(x, z, seed)`.
- **Caves:** `isCave(x, y, z, h)` excises stone with 3D fbm — `fbm3(x*0.09,
  y*0.09, z*0.09, 3) > 0.52` — guarded to `3 < y < h − 2`. Pure function of
  `(x, y, z, seed)`.
- **Trees:** `shouldPlaceTree(x, z, h)` is `h > SEA_LEVEL + 2 && h < 34 &&
  hash2(x, z, TREE_SEED ^ seed) < 0.02`. `placeTree` derives trunk height `4 +
  floor(hash2(wx*1.31, wz*2.97, TREE_SEED ^ seed) * 3)`, so a given column
  always produces the same tree at the same seed.
- **Cross-chunk overhang:** `generate` first fills the chunk's own 16×16
  columns, then scans a `(16 + 4) × (16 + 4)` ring of tree roots from 2 cells
  outside each edge (`tx` in `[x0 − 2, x0 + 18)`) and writes canopy/trunk
  cells that fall inside the chunk through the bounds-checked `setIfAir`.
  Combined with pure `heightAt`/`shouldPlaceTree`, any chunk can independently
  regenerate everything whose footprint reaches it — duplicate writes from
  neighboring chunks are harmless because the layout is deterministic and
  `setIfAir` only touches `Air`.

Why no `Math.random`: it is neither seeded nor reproducible; its sequence
differs per page load and per engine, breaking every guarantee above. All
stochastic-looking detail (noise, hashed trees) flows from `seed` + world
coordinates through `mulberry32`/`hash2`.

**Regeneration guarantee:** `new ChunkManager(scene, materials, seed)` →
same `seed` → identical `TerrainGenerator` → every `generate(chunk)` call
reproduces the exact previous block layout for that `(cx, cz)`, including
border-overhang foliage, so chunk unload/reload is visually lossless.

## Alternatives Considered

### `Math.random`-driven terrain
Rejected for the reasons above; also breaks the seed-loving `?seed=N` design
and makes the game state untestable (an automated browser check could not
reproduce a world).

### Deterministic hash-noise only (e.g. value noise from `hash2`)
Self-consistent and achievable, but value noise visibly blocks/lattices at the
zoom levels used here; simplex gives isotropic detail at equal cost. The
`hash2`-based path is still used for the binary decisions (tree placement,
trunk height) where coherence is not needed.

### World-serialized storage (save the world and reload chunks from disk)
Deterministic regeneration makes persistence optional; a pure function of the
seed costs zero bytes per block and never desynchronizes from the seed world.
Rejected as the primary mechanism (see ADR-004 for the in-session edit
overlay, which is the only state that is intentionally not a pure function of
the seed).

## Consequences

➕ **Chunk reload equivalence** — walking away and returning shows the exact
same terrain; no drift, no regeneration seams.

➕ **Border-safe chunking** — each chunk can be generated in isolation while
still carrying overhanging foliage, because every piece of information needed
at a border (height, tree presence, trunk height) is a pure function of world
coordinates.

➕ **Testable and reproducible** — unit tests can assert exact block layouts
for given seeds, and a browser session with `?seed=1337` is reproducible
across machines.

➕ **Zero persistence cost** — no per-block storage, no save files; the seed is
the entire world file.

➕ **Budget-friendly** — deterministic PRNG arithmetic (`imul`, shifts) has
steady, low cost, keeping 16,384 cells × (1 heightmap + ≤64 cave probes) per
chunk inside the 6 ms generation budget on typical hardware.

➖ **Fixed palette of shapes** — terrain variety is bound by the four noise
fields and the constant octaves/frequencies; changing them is a
world-generation "version bump" that changes every existing seed's world.

➖ **Denial/removal is hard** — there is no entity/bedrock-anchor system; the
pure-function world only changes through the edit overlay (pieces
in ADR-004).

➖ **Determinism across engines is assumed, not proven** — pure-javascript
arithmetic on integers is well-defined, but no automated cross-engine
regression test currently exists to prove seeds match in practice.
